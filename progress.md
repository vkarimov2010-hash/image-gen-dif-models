# Прогресс проекта

Сервис для сравнения моделей генерации изображений через kie.ai: один промт
и набор настроек уходит параллельно в несколько моделей, результаты
показываются рядом со стоимостью и возможностью скачать.

Полное описание архитектуры и решений — в плане:
`C:\Users\Владислав\.claude\plans\calm-percolating-stallman.md`.

## Статус: MVP реализован и работает

### Backend (FastAPI + SQLAlchemy + Alembic + PostgreSQL)
- Реестр моделей (`backend/app/registry.py`) — 12 text-to-image моделей
  kie.ai: Flux-2 Pro, Google Imagen 4 / Imagen 4 Ultra, Ideogram V3, GPT
  Image 2, Grok Imagine, Seedream 5.0 Lite, Qwen2, Google Nano Banana /
  Nano Banana 2 / Nano Banana 2 Lite, Z-Image — с маппингом style/aspect в
  параметры конкретной модели. Добавление новой модели kie.ai = один
  `ModelSpec`, без изменений фронта. GPT Image 1.5 сознательно не добавлен —
  дублирует GPT Image 2, а схема параметров в доках kie.ai не подтвердилась
  (см. ниже). У Z-Image подтверждён только параметр `prompt` — aspect_ratio
  не отправляется, формат изображения у неё всегда дефолтный модели.
  Выбор моделей для батча ограничен пятью одновременно (`schemas.py`,
  `GenerationForm.tsx`).
- Клиент к kie.ai (`backend/app/kie_client.py`): createTask/recordInfo,
  ретраи на сетевых сбоях и 5xx (не ретраит 4xx — бессмысленно).
- Параллельная генерация по всем выбранным моделям (`asyncio.gather`),
  независимый поллинг статуса каждой задачи, скачивание готовых изображений
  в локальное хранилище (`backend/app/storage.py`, абстракция под S3 позже).
- Роутеры: `/models`, `/generations` (создание/статус/история),
  `/generations/{id}/tasks/{id}/download`, `/credit`.
- Изоляция сбоев: ошибка одной модели в батче не роняет остальные.

### Frontend (React + Vite + TypeScript)
- Форма генерации: промт, стиль, пресеты назначения (аватар/пост/story/
  баннер → автоподстановка формата с возможностью переопределить), выбор
  нескольких моделей чекбоксами, оценка стоимости батча до генерации.
- Подсказка под Seed: какие из выбранных моделей его реально используют
  (`supports_seed` из реестра) — поле одно на весь батч, но часть моделей
  API-параметра для seed не имеет и значение для них молча пропадает.
- Предупреждение под промтом: эвристика по ключевым словам
  (`STYLE_CONFLICT_KEYWORDS` в `styleOptions.ts`) — если похоже, что в
  тексте промта пользователь сам упомянул стиль, отличный от выбранного в
  форме. Наш код не понимает промт семантически, просто дописывает суффикс
  выбранного стиля в конец текста (`_with_style_suffix` в
  `backend/app/registry.py`), поэтому конфликтующие формулировки уходят в
  модель вместе без разрешения противоречия на нашей стороне — предупреждение
  только информирует, не блокирует отправку.
- Экран результатов: сетка карточек по моделям с поллингом статуса,
  стоимостью, скачиванием, **полноэкранный лайтбокс по клику на превью**.
- История/галерея прошлых генераций.
- Бейдж баланса kie.ai в шапке.

### Инфраструктура
- `docker-compose.yml`: db (Postgres) + backend + frontend, миграция
  применяется автоматически при старте backend-контейнера.
- Volume-монтирование исходников backend/frontend в контейнеры — правки
  кода подхватываются на лету (Vite HMR / uvicorn `--reload`) без ребилда.
  Помимо `frontend/src` и `index.html` теперь домонтирован и
  `vite.config.ts` — без него правка `server.watch.usePolling` (нужна на
  Windows, где Docker Desktop не пробрасывает нативные fs-события bind-mount
  в контейнер) физически не попадала в контейнер, и то, что раньше выглядело
  как "фикс", на самом деле было лишь следствием полного рестарта контейнера
  (свежий процесс читает файлы с диска заново, а не обновляет их через HMR).
- Порты по умолчанию заняты другими локальными проектами пользователя,
  поэтому смэппены нестандартно: db → `5433:5432`, frontend → `5175:5173`,
  backend → `8000:8000` (без изменений).

  1536×1536. Фактическая стоимость **0.8 кредита** (оценка в реестре

Остальные 7 новых моделей реестра (Imagen 4 Ultra, GPT Image 2, Grok
Imagine, Seedream 5.0 Lite, Qwen2, Nano Banana, Nano Banana 2 Lite) собраны
по документации docs.kie.ai, но ни разу не прогонялись с реальным ключом.
Наибольший риск — aspect_ratio-enum для Nano Banana 2 Lite (взят по
аналогии с Nano Banana 2, чья страница не отдавала полный список значений)
и `enable_pro` у Grok Imagine (параметр не передаётся, используется дефолт
API). После бага с Z-Image (обязательный параметр, отсутствующий в открытых
источниках) стоит относиться к любой ещё не проверенной модели насторожённо
— доки docs.kie.ai не всегда дают полную картину обязательных полей.

## Найденные и исправленные баги (в ходе этой проверки)
- **`kie_client.py::get_task_result`**: `data.get("data", {})` не защищает
  от случая, когда ключ `"data"` в ответе присутствует, но его значение
  — явный `null` (а не отсутствует как ключ) — тогда `.get(...)` вернул бы
  `None`, а не дефолт `{}`, и следующий `payload.get("state", ...)` падал
  с `'NoneType' object has no attribute 'get'`. Именно так себя повёл
  ответ kie.ai на невалидный `createTask` для Z-Image. Исправлено на
  `data.get("data") or {}` — общий фикс, не специфичный для одной модели.
- **`registry.py::_build_zimage_input`**: изначально не отправлял
  `aspect_ratio`, хотя эта модель требует его обязательно (`createTask`
  отвечает `500 "This field is required"` без него) — подтверждено вручную
  прямыми запросами к kie.ai. Добавлен маппинг аспектов, идентичный
  остальным моделям (`1:1/4:3/3:4/9:16/16:9`); `"auto"` API не принимает.

## Известная проблема (не наш баг)
Ideogram V3 и Google Imagen 4 несколько раз подряд возвращали мгновенный
(`0–15 мс`) `failCode: 500, "internal error, please try again later"` с
нулевым списанием кредитов — при этом Flux-2 с точно той же архитектурой
запроса на нашей стороне отрабатывает нормально. Формат запроса к обеим
моделям сверен с документацией kie.ai повторно — расхождений нет. Похоже на
временную нестабильность именно этих двух моделей на стороне kie.ai.

**Возможное улучшение (не сделано, обсуждалось с пользователем):**
автоматический повтор `createTask` при таком transient-фейле (сейчас
ретраятся только сетевые/HTTP-ошибки самого запроса, а не сбой уже принятой
в обработку задачи).
